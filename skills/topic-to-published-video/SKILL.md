# Topic to Video：选题到成片

把用户的一个选题或观点推进到可发布的视频。负责流程编排与质量控制，按需调用环境中已有的生成、转写、数字人和剪辑工具。先确认内容框架，先审画面再定稿口播，随后用真实音频时间完成剪辑包装。

## 启动与续作

完整制作先读 [阶段工作流](references/workflow.md) 与 [交付物约定](references/artifacts.md)。进入审阅时读 [质量检查](references/quality-gates.md)；已有音频、SRT 或成片修改时读 [实录对齐与包装](references/recorded-packaging.md)。

为用户作品创建独立目录，维护 `production-state.md`。用户说“继续”时读取状态，推进下一个未完成阶段；保留已通过的素材，不从头重做。

启动时输出并保存：目标观众、核心痛点、核心观点、结果承诺、内容框架、建议平台/画幅/时长、口播草稿及配片提示词。没有平台和画幅时可暂用 16:9，并明确为可调整建议；不要把某位创作者的署名、片尾、配色或人物身份设为通用默认。

## 核心规则

- **先审画面，再定稿口播**：草稿用于规划素材；检查素材实际表达，再调整和锁定文案。已有最终实录时以实录为准，调整画面，除非用户明确授权改写和重录。
- **真实时间驱动**：SRT 来自实际音频；逐词时间仅在工具支持且已获取时交付。没有音频时标记 `pending_audio`，不伪造正式时间。
- **每句口播都有画面责任**：出镜、配片、章节卡、解释图和总结按信息需要分配。动态应帮助理解，不能用无关背景掩盖内容缺口。
- **少问、关键处确认**：框架、素材审阅与口播定稿、视觉方向、分镜、审阅版、封面文案是关键节点。用户已授权的选择不重复确认；全自动模式按用户指定范围执行并记录假设。
- **修改同步下游**：脚本、实录时间、视觉规范、分镜和素材清单各有唯一依据；改动导致下游失效时更新状态。
- **能力如实报告**：没有生成、数字人、转写或渲染工具时，完成可执行文案和计划，说明缺什么与下一步，不声称已生成成片。

## 按能力选择工具

先盘点可用工具，只加载当前阶段所需技能。以下是可选适配路线，不是本仓库捆绑的依赖：

| 任务 | 可选工具/技能 |
| --- | --- |
| B-roll 生成 | 已配置的 MiniMax H3 接口、AutoDL B-roll 工具、其他视频生成服务 |
| 真人替代 | 可用的数字人或配音工具，或用户提供的成品出镜素材 |
| 多段合并与字幕对齐 | ChatCut、可用的转写与剪辑工具 |
| 风格图、解释图、封面 | 可用图像生成工具 |
| 动态包装与渲染 | HyperFrames 或 Remotion 及对应技能 |
| 音乐与验收 | 可用音乐、音频处理、抽帧和视频检查工具 |

用户指定工具时优先采用；工具缺失则交付提示词、镜头计划和接入要求。不要猜测 API 参数、凭据、服务价格或未验证的能力。外部工具按各自许可使用，付费生成遵守用户授权预算；失败重试不能无限消耗费用。

## 复盘与完成

审阅通过后交付最终视频、字幕、工程源文件、素材清单、封面、发布文案与审阅记录。逐词字幕、数字人、音乐等按制作方案和工具能力交付，明确列出未完成项。

在项目中记录用户确认的偏好和本次反馈，供后续项目明确选择复用。只有用户要求更新 Skill 或持久偏好时才修改对应文件；不要宣称模型会自动训练或把私人偏好上传公开仓库。
