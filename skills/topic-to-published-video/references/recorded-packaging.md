# 实录对齐与成片包装

当项目已经有真实口播、SRT、A-roll、生成画面，或用户正在反复修改解释段、总结段和片尾时，使用本参考。

## 1. 先确定新的唯一真源

- 默认以已锁定口播和真实 SRT 决定文字与时间，画面按口播重排或补生成。
- 若用户明确要求“根据现有画面反推口播”，先按素材实际内容重写口播，不再维护限制画面的故事线；用户重新录制后，新音频/SRT 立即取代旧版本。
- 每次换录音都重新检查章节边界、字幕、解释卡、总结段和片尾起点，不能只替换音轨。
- 用户要求保留某类实拍片段时，先盘点全部片段：人物有效段必须覆盖，白场、闪白、空白帧和误拍段不得当作可用内容。

## 2. 逐句对齐，而不是按主题猜画面

为每个字幕片段记录“这句话的视觉责任”：主体、动作、运镜、关系变化和最终信息。已有素材不匹配时按顺序处理：

1. 在现有素材中换到语义更接近的镜头。
2. 调整镜头起止点，让动作落在关键词上。
3. 若用户授权以画面为准，改写并重录该句口播。
4. 仍无法对应时，只补生成缺失片段，不重做已经合格的整套素材。

不要用抽象故事线解释明显不对应的画面。教学视频首先要让观众在当前画面里直接看见口播所说的变化。

## 3. 章节解释段的稳定结构

知识型章节优先使用两步结构：

1. **动态例证**：先播放能直接看出效果的实际画面。
2. **结构解释**：在章节末尾出现解释包装，至少说明“是什么、适合表达什么、与相近概念的区别”。

需要机位、运动路径或主体关系图时：

- 优先用 `imagegen` 生成风格统一的独立设计元素，而不是临时 CSS 火柴图。
- 每种概念生成真正不同的语义图，不只换标题：推拉表现距离，摇表现原地转向，移表现机位位移和视差，跟表现恒定主体关系，升降表现高度，环绕表现背景关系。
- 请求透明素材时必须检查真实 alpha 通道；不要把黑色或白色底图误当透明图。
- 在画面中按统一尺寸、留白、标签和光影放置，先渲染全部章节联系表，检查错图、裁切和风格漂移。

## 4. 总结段不是“停住”，也不是继续放无关视频

总结段应从持续移动的背景视频切换到信息主导的总览，但稳定底板不等于没有动态。可用的动态必须帮助理解结构，例如：

- 阶段编号和总进度。
- 标题遮罩揭示、关键词分层入场。
- 卡片按口播顺序错位进入。
- 运动路径、节点连线和强调条逐步绘制。
- 克制的扫描光、颗粒或景深粒子维持生命感。
- 最终结论使用独立收束动画，而不是普通卡片继续堆字。

避免重新加入持续运动且无语义的 B-roll，也避免所有页面只做同一种淡入。至少检查每个阶段的入场、稳定和退场帧，并看片段运动而不只看静帧。

## 5. 新片尾素材仍需要包装

用户提供真人片尾或“关注我”素材时，不能只把视频裸放到时间轴：

- 先检查画幅、时长和是否自带音频，判断是替换旧片尾还是追加。
- 若使用新片尾原声，在切点结束旧口播和旧字幕，避免双重人声及错误字幕。
- 沿用项目视觉系统增加品牌标题、行动提示、边框或角标、标签、进度线和入退场；包装不得遮挡眼睛、嘴部或关键手势。
- 人物占一侧时，把信息组织在另一侧；用渐变控制背景可读性，不用大块面板生硬盖住人物。
- 片尾最后需要视觉和音乐一起淡出，不能让素材或音轨突然截断。

## 6. 全程背景音乐

- BGM 必须覆盖主片、总结和后来追加的片尾；短曲用循环并让音量曲线跨循环连续。
- 开头淡入、结尾淡出；人声出现时音乐保持明显更低。若音乐存在但用户几乎听不到，检查源音乐响度和实际混音，不要只确认时间轴上“有一条音乐”。
- 新片尾自带人声时仍保留 BGM，但继续服从人声优先。
- 渲染后确认输出确实有音轨，并抽查主片、总结、片尾三个区间的音量和声道。

## 7. 修改后的验收顺序

1. 类型检查或项目构建检查。
2. 每个章节解释页输出一张稳定帧并做联系表。
3. 总结段每个阶段至少输出一张稳定帧，另看一次完整运动。
4. 片尾抽查前、中、后三帧，确认包装出现、保持、退出正常。
5. 完整渲染后检查尺寸、帧率、时长、视频/音频编码和全片解码。
6. 保留版本号清晰的新文件，不覆盖用户原始素材与上一审阅版。
